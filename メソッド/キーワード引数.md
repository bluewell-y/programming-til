# キーワード引数

前提：[引数.md](./引数.md)、[デフォルト値.md](./デフォルト値.md)

## 学んだこと

引数に「名前」をつけて渡す書き方。通常の引数は「渡す順番」で対応が決まるが、キーワード引数は「名前」で対応が決まるため、渡す順番を入れ替えても結果が変わらない。

## コード

### 基本の書き方

```ruby
def greet(name:, time:)
  puts "#{name}さん、#{time}"
end

greet(name: "田中", time: "おはようございます")
# => 田中さん、おはようございます
```

- `def greet(name:, time:)` → 引数名の後ろに `:` をつけると、名前を指定して渡してもらう約束になる
- 呼び出し側も `引数名: 値` の形で渡す

### 順番を入れ替えても結果は変わらない

```ruby
greet(time: "おはようございます", name: "田中")
# => 田中さん、おはようございます（順番を変えても同じ結果）
```

### デフォルト値付きのキーワード引数

```ruby
def greet(name:, time: "こんにちは")
  puts "#{name}さん、#{time}"
end

greet(name: "田中", time: "おはようございます")
# => 田中さん、おはようございます

greet(name: "鈴木")
# => 鈴木さん、こんにちは（time を省略したのでデフォルト値が使われる）
```

- `name:` → デフォルト値なし。必ず渡す必要がある（渡さないとエラー）
- `time: "こんにちは"` → デフォルト値あり。省略すればこの値が使われる
- 1つのメソッドの中で、必須のキーワード引数とデフォルト値ありのキーワード引数を混在させられる

## 通常の引数との比較

| 書き方 | 対応の決まり方 | 順番を変えると |
|---|---|---|
| `def greet(name, time)` | 渡す順番 | 結果が変わってしまう |
| `def greet(name:, time:)` | 名前（キーワード） | 順番を変えても結果は同じ |

## 発生した問題・エラー（概念として確認したもの）

必須のキーワード引数（デフォルト値なし）を渡し忘れると、エラーになる。

- 原因：`def greet(name:, time:)` は「両方とも名前付きで渡す」という約束になっているため、渡し忘れると約束違反になる
- 想定されるエラー：`missing keyword: :time`（「timeというキーワードが渡されていません」という意味）
- 対処：必須のキーワード引数は、呼び出し時に必ず渡すか、デフォルト値を設定しておく

## 重要なポイント

- キーワード引数は「名前」で対応が決まるため、順番を気にしなくてよく、引数が増えても可読性が保たれる。
- `引数名:` だけ → 必須（渡さないとエラー）。
- `引数名: 既定値` → 省略可能（省略時はデフォルト値が使われる）。
- 通常の引数とキーワード引数を組み合わせて使うこともできる。
